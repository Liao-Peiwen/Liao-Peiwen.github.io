10:T103c,<h1>Lightsail と EC2 の選び方と移行パターン</h1>
<p>AWS では、<strong>Lightsail</strong> と <strong>EC2</strong> のいずれも仮想サーバを提供しますが、目的や規模に応じて選択基準が異なります。<br>本記事では、両者の特性、代表的な構成例、Terraform によるコード例、そして移行の流れを解説します。</p>

<h2>どちらを選ぶべきか</h2>
<h3>Lightsail（シンプル・省運用）</h3>
<ul>
<li>OS、ミドルウェア、アプリケーションをまとめた<strong>統合イメージ</strong>が用意されており、数分で環境を立ち上げ可能。</li>
<li><strong>固定帯域・月額課金制</strong>でコストを予測しやすい。</li>
<li><strong>管理コンソールで完結</strong>する操作性が高く、小規模チームや MVP 開発に適している。</li>
<li>一方で、<strong>カスタマイズ性や拡張性は限定的</strong>。</li>
</ul>
<h3>EC2（柔軟・拡張志向）</h3>
<ul>
<li>OS、Web サーバ、アプリケーション、DB などを<strong>自由に構成可能</strong>。</li>
<li><strong>VPC / ALB / Auto Scaling / IAM / CloudWatch</strong> など、他の AWS サービスと密に統合できる。</li>
<li>中〜大規模システム、セキュリティ要件や可用性が重視されるプロジェクトに最適。</li>
<li>ただし、<strong>運用・保守の負担は高め</strong>。</li>
</ul>

<h2>代表的なアーキテクチャ構成</h2>
<ol>
<li><p><strong>単一インスタンス構成</strong></p>
<ul>
<li>EC2（Nginx + PHP-FPM + DB）</li>
<li>開発・検証環境や小規模サイト向け。</li>
</ul>
</li>
<li><p><strong>三層構成</strong></p>
<ul>
<li>EC2（Web）＋ RDS（DB）＋ S3 / CloudFront（静的アセット配信）</li>
<li>一般的な WordPress や業務系 Web システムで採用される構成。</li>
</ul>
</li>
<li><p><strong>スケーラブル構成</strong></p>
<ul>
<li>ALB ＋ Auto Scaling Group（EC2）＋ RDS Multi-AZ ＋ S3 ＋ ElastiCache</li>
<li>高トラフィック対応、冗長構成、セッション共有を考慮した設計。</li>
</ul>
</li>
</ol>

<h2>Terraform による EC2 デプロイ例（抜粋）</h2>
<pre><code class="language-hcl">resource "aws_instance" "wp" {
  ami           = "ami-xxxxxxxx"
  instance_type = "t3.small"
  # user_data 内で Nginx / PHP / WordPress を自動セットアップ
}
</code></pre>
<p>インフラをコード化（IaC）することで、再現性・可搬性の高い環境構築が可能になります。<br>チーム開発では GitOps や CI/CD パイプライン と組み合わせることで、安定したリリース運用が実現できます。</p>

<h2>Lightsail から EC2 / RDS への移行ステップ</h2>
<ol>
<li><p><strong>データエクスポート</strong></p>
<ul>
<li>wp-cli や WordPress 用の移行プラグインを利用し、DB をエクスポート。</li>
</ul>
</li>
<li><p><strong>データベース移行</strong></p>
<ul>
<li>エクスポートしたデータを RDS にインポート。</li>
</ul>
</li>
<li><p><strong>アプリケーション移設</strong></p>
<ul>
<li>EC2 上に WordPress / PHP / Nginx を構築し、RDS へ接続設定を変更。</li>
<li>wp-config.php の接続情報を更新。</li>
</ul>
</li>
<li><p><strong>メディアファイルのホスティング</strong></p>
<ul>
<li>画像・動画などの静的ファイルを S3 に配置し、CloudFront で配信。</li>
</ul>
</li>
<li><p><strong>DNS 切り替え・ロールバック対応</strong></p>
<ul>
<li>Route 53 などで新環境のドメインを指すよう設定し、問題発生時に即座に戻せるよう冗長設計。</li>
</ul>
</li>
</ol>

<h2>まとめ</h2>
<ul>
<li><strong>Lightsail</strong>：スピード重視・簡易運用に最適。</li>
<li><strong>EC2</strong>：拡張性・統合性を求める場合に選択。</li>
<li>規模拡大に合わせて Lightsail → EC2 / RDS へシームレスに移行できる設計を意識することで、将来的な運用コストを最小化できます。</li>
</ul>
