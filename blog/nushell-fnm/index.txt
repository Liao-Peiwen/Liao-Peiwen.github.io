10:T1653,<h1>Nushell で fnm を用いて Node.js を利用する設定手順</h1>
<p>Nushell 上で <code>node</code> コマンドを確実に解決させるためには、<code>fnm env</code> が出力する環境変数（特に <code>FNM_MULTISHELL_PATH</code>）を Nushell の <code>PATH</code> に適切に反映させる必要があります。本記事では、その最小設定と検証プロセスをまとめます。</p>

<h2>バージョン</h2>
<table>
<thead>
<tr>
<th>名称</th>
<th>バージョン</th>
</tr>
</thead>
<tbody><tr>
<td>Nushell</td>
<td>0.98.0</td>
</tr>
<tr>
<td>fnm</td>
<td>1.37.1</td>
</tr>
</tbody></table>

<h2>結論（$nu.env-path に記述する内容）</h2>
<p>Nushell の環境初期化ファイル（<code>$nu.env-path</code>）に、次の設定を追加します。</p>
<pre><code class="language-nu"># 参考: PATH のエントリ追加の一般的パターン（Nushell Book より）
# $env.PATH = ($env.PATH | split row (char esep) | prepend '/some/path')
# あるいは stdlib の `path add` を使う方法もある:
# use std "path add"
# $env.PATH = ($env.PATH | split row (char esep))
# path add /some/path
# path add ($env.CARGO_HOME | path join "bin")
# path add ($env.HOME | path join ".local" "bin")
# $env.PATH = ($env.PATH | uniq)

# fnm が出力する環境変数を JSON として受け取り、まとめて取り込む
fnm env --json | from json | load-env

# Linux では node バイナリが `$env.FNM_MULTISHELL_PATH / "bin"` 配下になる点に注意
# ここではクロスプラットフォーム向けに multishell パス自体を PATH 先頭に加える
$env.PATH = (
  $env.PATH
  | split row (char esep)
  | prepend $env.FNM_MULTISHELL_PATH
  | uniq
)
</code></pre>
<p>補足:</p>
<ul>
<li>Linux のみ <code>($env.FNM_MULTISHELL_PATH | path join "bin")</code> を使うアプローチも可能です。</li>
<li>既存 PATH と重複しないよう <code>uniq</code> でユニーク化しています。</li>
</ul>

<h2>検証プロセス</h2>
<h3>1) fnm env の基本挙動（PowerShell の例から把握）</h3>
<p>fnm の README では PowerShell 用に次の初期化が案内されています。<br><a href="https://github.com/Schniz/fnm?tab=readme-ov-file#powershell">https://github.com/Schniz/fnm?tab=readme-ov-file#powershell</a></p>
<pre><code class="language-sh">fnm env --use-on-cd --shell power-shell | Out-String | Invoke-Expression
</code></pre>
<p>この出力には、<code>$env:FNM_LOGLEVEL = "info"</code> のような環境変数設定が含まれます。<br>つまり <code>fnm env</code> は各シェル向けの「環境変数設定スクリプト」を生成するコマンドです。</p>
<h3>2) fnm env の内部実装の要点</h3>
<p>fnm の実装（Rust）を確認すると、<code>env</code> サブコマンドは <code>FNM_MULTISHELL_PATH</code> などを生成し、Windows では <code>PATH</code> の先頭に <code>FNM_MULTISHELL_PATH</code> を挿入する文字列を出力します。</p>
<ul>
<li><a href="https://github.com/Schniz/fnm/blob/master/src/commands/env.rs"><code>src/commands/env.rs</code></a>（抜粋の要旨）<ul>
<li><code>FNM_MULTISHELL_PATH</code> を算出</li>
<li>シェル種別に応じて <code>PATH</code> へ追加する文字列を生成</li>
<li>Windows: <code>FNM_MULTISHELL_PATH</code> をそのまま <code>PATH</code> へ</li>
<li>Unix: <code>FNM_MULTISHELL_PATH/bin</code> を <code>PATH</code> へ</li>
</ul>
</li>
</ul>
<p>このため、Nushell でも同様に <code>FNM_MULTISHELL_PATH</code> を <code>PATH</code> に入れる必要があります。</p>
<h3>3) Nushell での取り込み（load-env まで）</h3>
<p>Nushell では <code>fnm env --json</code> を使うと JSON 形式で環境変数の集合を取得できます。<br><code>from json</code> で <code>record</code> に変換し、<code>load-env</code> で一括反映します。</p>
<p>参考: <a href="https://www.nushell.sh/book/environment.html#load-env">Nushell Book: Environment</a></p>
<pre><code class="language-nu"># そのまま load-env すると型不一致になるため、まず JSON を record 化する
fnm env --json | from json | load-env

# 反映確認
$env.FNM_LOGLEVEL
# =&gt; info 等
</code></pre>
<h3>4) PATH の調整と Node 実行確認</h3>
<p><code>FNM_MULTISHELL_PATH</code> を <code>PATH</code> に追加した後、<code>node --version</code> が解決できることを確認します。</p>
<pre><code class="language-nu">$env.PATH = (
  $env.PATH
  | split row (char esep)
  | prepend $env.FNM_MULTISHELL_PATH  # Linux は join "bin" も検討
  | uniq
)

node --version
# =&gt; vXX.YY.ZZ
</code></pre>

<h2>まとめ</h2>
<ul>
<li><code>fnm env --json | from json | load-env</code> で fnm の環境変数を Nushell に一括適用できる。</li>
<li>さらに <code>FNM_MULTISHELL_PATH</code> を <code>PATH</code> に追加することで、<code>node</code> が解決される。</li>
<li>設定は <code>$nu.env-path</code> に記述しておくと、起動時に自動で反映される。</li>
</ul>
